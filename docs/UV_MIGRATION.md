# uv dependency-management migration

This repository uses `pyproject.toml` as the single Python dependency declaration and `uv.lock` as the reproducible resolved graph.

## Local development

The preferred setup is through `scripts/setup_env.sh` or `scripts\\setup_env.bat`. The setup wrappers resolve uv in this order: project-managed copy under `tools/uv/`, system `uv`/`uv.exe` from `PATH`, and, only when neither exists, the official installer into `tools/uv/`.

The same resolution contract is now used by all source-checkout consumers. POSIX wrappers use `scripts/lib/resolve_uv.sh`; Windows wrappers use `scripts/lib/resolve_uv.bat`. The project-managed executable always wins over a global installation.

This matters because activating `.venv` does not put `tools/uv/uv` on `PATH`. A correctly bootstrapped machine therefore must not fail merely because `command -v uv` or `where uv.exe` cannot find a global executable.

Run project commands with the resolved uv environment:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run python main.py doctor
uv run python main.py run --help
```

## Affected wrappers

The shared resolver is consumed by:

- `scripts/run_local.sh` / `scripts/run_local.bat`;
- `scripts/run_unattended.sh` / `scripts/run_unattended.bat`;
- `scripts/setup_rclone.sh` / `scripts/setup_rclone.bat`;
- `scripts/setup_google.sh` / `scripts/setup_google.bat`;
- `scripts/build_linux.sh` / `scripts/build_windows.bat`.

`run_unattended.*` continues to prefer packaged executables before source-checkout execution and retains the direct `.venv` Python fallback when uv cannot be resolved.

## Regression contract

`tests/test_uv_resolution_contract.py` verifies:

- project-managed uv has priority over `PATH`;
- POSIX wrappers use the shared resolver;
- Windows wrappers use the shared resolver;
- the build/setup entry points invoke `%UV_BIN%` or `$UV_BIN` rather than a bare global uv;
- unattended wrappers retain their packaged-executable priority;
- wrappers no longer make a global uv lookup a mandatory precondition.

## Local translation during setup

The setup wrappers can also prepare the configured pinned local translation model with `--local-translation`. This remains opt-in because the default MADLAD-400 3B model is large.

## Lockfile policy

`uv.lock` is committed and must be generated by uv. CI uses `uv lock --check` and `uv sync --locked`. Dependency upgrades are explicit operations followed by the complete CI matrix.

## CI and packaging

CI uses uv for Python provisioning, environment synchronization, tests, linting, compilation, audits and package builds. The clean wheel gate deliberately uses pip to prove that uv is not a runtime requirement of installed packages.

## CUDA exception

Portable CUDA runtime installation intentionally retains its controlled pip fallback for packaged environments that do not ship with uv. This is independent of the source-checkout wrapper resolution contract.
