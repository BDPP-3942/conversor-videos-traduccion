# uv dependency-management migration

This repository uses `pyproject.toml` as the single Python dependency declaration and `uv.lock` as the reproducible resolved graph.

## Local development

The preferred first-time setup is through the repository setup wrapper:

```bash
./scripts/setup_env.sh
```

or on Windows:

```bat
scripts\setup_env.bat
```

The wrappers resolve uv in this order: an existing project-managed copy under `tools/uv/`, a system `uv`/`uv.exe` from `PATH`, and finally the official uv installer into `tools/uv/` when neither is available. The managed copy is ignored by Git and the installer runs without modifying shell profiles.

After bootstrap, the setup creates the project environment and synchronizes the locked development dependencies:

```bash
uv python install 3.13
uv sync --group dev
```

Run commands through the project environment:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run python main.py doctor
uv run python main.py run --help
```

Optional features are enabled with extras:

```bash
uv sync --extra google
uv sync --extra tts
```

## Project-managed uv consumer contract

Bootstrap and consumers use the same resolution policy:

1. project-managed `tools/uv/uv` on POSIX or `tools\uv\uv.exe` on Windows;
2. system `uv`/`uv.exe` from `PATH`;
3. only `setup_env.*` installs a missing managed copy.

The shared resolvers are:

- `scripts/lib/resolve_uv.sh`;
- `scripts/lib/resolve_uv.bat`.

The following source-checkout consumers use the resolved executable rather than assuming that a global uv is installed:

- `scripts/run_local.sh` / `scripts/run_local.bat`;
- `scripts/run_unattended.sh` / `scripts/run_unattended.bat`;
- `scripts/setup_rclone.sh` / `scripts/setup_rclone.bat`;
- `scripts/setup_google.sh` / `scripts/setup_google.bat`;
- `scripts/build_linux.sh` / `scripts/build_windows.bat`.

`run_unattended.*` continues to prefer packaged executables before source-checkout execution and retains the direct `.venv` Python fallback when uv cannot be resolved.

## Local translation during setup

The setup wrappers can also prepare the configured pinned local translation model:

```bash
./scripts/setup_env.sh --local-translation
```

The Windows equivalent is:

```bat
scripts\setup_env.bat --local-translation
```

This is intentionally opt-in because the default MADLAD-400 3B model is approximately 2.95 GB. If model preparation is deferred, the supported standalone command remains:

```bash
uv run python scripts/manage_local_translation.py download
```

## Lockfile policy

`uv.lock` is committed and must be generated by uv. It is never hand-edited. CI uses:

```bash
uv lock --check
uv sync --locked ...
```

Dependency upgrades are explicit operations, for example `uv lock --upgrade-package <name>`, followed by the complete CI matrix.

## CI

CI uses uv for Python provisioning, environment synchronization, tests, linting, compilation, audits and package builds. The dependency cache is uv's cache rather than pip's cache.

The clean wheel gate intentionally remains:

```bash
python -m pip install dist/*.whl
python -m pip check
```

This proves that the published wheel remains consumable by standard pip users. uv is the project development/build manager; it is not a runtime requirement for installed wheels.

## Scripts and schedulers

- `scripts/run_local.*` dispatches through the resolved project-managed uv.
- `scripts/run_unattended.*` prefers a packaged executable, then resolved uv-managed execution, preserving the existing executable-first behavior for schedulers.
- `scripts/run_scheduled.*` continues to delegate to the unattended wrapper.
- Linux and Windows PyInstaller scripts use the resolved uv for synchronization/build commands.
- Google setup uses the resolved uv for `sync --extra google`.
- TTS dependency installation is performed by uv; `scripts/setup_tts.py` only bootstraps Kokoro model assets.

## CUDA exception

The application can be distributed as a portable executable that does not contain uv. Therefore the managed CUDA runtime installer prefers `uv pip install --target ...` when uv is available, but deliberately retains a pip fallback for packaged runtime environments. This is the only intentional dependency-installation fallback in the application runtime.

The CUDA driver and global Toolkit are never replaced by this operation.

## External rclone

`rclone` is an external executable, not a Python dependency. `requirements-rclone.txt` is therefore not migrated into uv and remains documentation for that external tool only.

The repository uses a managed-rclone contract: the application downloads a pinned rclone release into `tools/rclone/`, verifies the release archive SHA-256 from the official `SHA256SUMS`, and invokes the binary with the project-local configuration under `secrets/rclone/rclone.conf`. A global `rclone` installation is neither required nor used by the managed path.

The supported setup path is:

```bash
uv run python main.py provider bootstrap
uv run python main.py provider setup-rclone --help
uv run python main.py provider verify rclone --profile <profile> --location input
```

`./scripts/setup_rclone.sh` and `scripts\setup_rclone.bat` are wrappers around the same resolved uv bootstrap. `scripts/setup_env.sh --rclone` and `scripts/setup_env.bat --rclone` bootstrap the managed binary; they do not probe or require a system-wide `rclone` executable.

Runtime behavior is deterministic: storage providers use `settings.rclone_binary_file` and `settings.rclone_config_file`, never PATH lookup. Credentials and `rclone.conf` remain outside version control.

## Regression contract

`tests/test_uv_resolution_contract.py` verifies project-managed uv precedence over `PATH`, POSIX/Windows wrapper integration, build/setup invocation through the resolved executable, unattended fallback behavior and the absence of a mandatory global uv lookup.

## Historical release documentation

The migration documentation describes the current `1.8.3` candidate without replacing the historical release record. `1.8.1` and `1.8.2` are published releases and their historical documentation remains final and immutable.
