# VTT repair and TTS recovery

## Why this exists

The silence-aware STT stage can create more subtitle cues from a single Whisper segment. Every generated cue must have `start < end`. Existing VTT files created by older pipeline versions may not satisfy that invariant, and a translated VTT can also become invalid independently.

The repair layer handles the three relevant cases without regenerating the already processed video:

1. **Original/STT VTT invalid or missing**: reuse the existing MP4/WebM as the media source, run STT again, validate the new cues, then translate them.
2. **Original VTT valid, translated VTT invalid or missing**: keep the original timestamps and run translation again. STT is not repeated.
3. **Both VTTs invalid**: run STT once on the existing video, validate it, then generate a new translated VTT from those timestamps.

A valid VTT is not regenerated. The original video is never regenerated by the repair layer.

## Automatic TTS flow

When `TTS_ENABLED=true`, the common storage pipeline invokes the TTS stage after the translated VTT is available. Before synthesis, the pipeline validates the subtitle artifacts and invokes the repair layer when necessary.

The effective flow is:

```text
run
  -> STT / resume
  -> translation / resume
  -> validate original + translated VTT
  -> repair only when invalid or missing
  -> TTS
  -> translated audio
  -> *_tts.mp4
  -> *_tts.webm when enabled and a WebM source exists
```

This is shared by the local, Google Drive and rclone storage providers because TTS is implemented as a storage decorator around the common pipeline.

## Safety guarantees

- `start >= end` is never accepted as a valid subtitle cue.
- New STT cues with invalid intervals are discarded before VTT generation.
- Generated VTT files are validated before replacing an existing file.
- Existing VTTs are backed up before replacement.
- A TTS failure does not delete a valid source video or subtitle file.
- The main video is not regenerated merely to repair subtitles.
- Existing completed TTS artefacts are reused on subsequent runs.

## Manual verification

For an existing output folder, inspect both:

```text
<output-folder>/original_transcriptions/*_original.vtt
<output-folder>/*_<target-lang>.vtt
```

Then run the normal pipeline with TTS enabled. The TTS stage will repair invalid subtitle artifacts before synthesis.
